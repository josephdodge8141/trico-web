# TriCo UX improvement plan

This plan follows the [six-page UX audit](./ux-audit/2026-10-05-public-pages.md) and its per-page source traces. It applies to the existing `codex/trico-full-frontend-rewrite` branch. The target is a usable public site with each audited category at **8/10 or better on independent re-review**, while retaining authenticated in-page editing and published-content safety. A score is an outcome measure, not a substitute for the functional checks below.

## Implementation checkpoint

The running local preview is [app.localhost:18090](http://app.localhost:18090/). The shared public header is in use on the six main routes; its mobile control and keyboard dismissal pass the revised canonical behavior. Public inquiry forms now send through a validated backend route to local Mailpit and preserve input on delivery failure. The shared careers form stages the selected PDF or Word file in a private bucket with a short lived signed upload, then submits only an upload reference; it attaches the file to local Mailpit delivery and shows success only after the mailbox send completes. Real Estate listings and the Property Management, Real Estate team, and Development collections use the template Tabs primitive. Empty review destinations, numbered partner names, unavailable portfolio photos, unfinished profile copy, dated sample updates, and sample vacancies are withheld from public presentation while the CMS retains their editable records. Home updates and vacancies and Property Management and Real Estate testimonials now share an explicit public visibility selection in the editor; older custom content keeps its prior visibility until reviewed, and new records start hidden. Construction now combines the empty Current and Completed project states into one honest request path while retaining separate editable collections. Route-specific React, authenticated editing controls, and uncommon CMS icons now load on demand; the complete seed catalog loads only in server code. Fresh public visits transfer 215–232 KB of encoded JavaScript instead of 384–395 KB.

The [eighth independent six-page re-score](./ux-audit/2026-10-05-public-pages-rescore-8.md) covers the public rendering after testimonial, news, and vacancy suppression and lazy image loading. Its 12 desktop/mobile screenshots show **8.0 for Home, Property Management, Real Estate, Storage, and Development; 7.9 for Construction**. A [focused Construction re-score](./ux-audit/2026-10-05-construction-rescore-9.md) confirms that hiding all three unverified “500+ Projects Completed” presentations and removing the resulting empty About card leaves a usable page, but Construction remains **7.9**. Its sole remaining 7 is conversion: no approved current or completed project example is published. The page presents an honest request path until the owner supplies project evidence. Suppressing unapproved content improved factual presentation but did not itself raise a usability score.

An October 6 follow-up uses the owner's Lovable preview as the careers content reference: its Home page lists Property Manager, Project Coordinator, Leasing Agent, and Administrative Assistant. Those exact four seed roles are now approved for public display; the vacancy suppression described in the earlier checkpoint is superseded. The resume invitation has more separation from role results. Home milestones use the generic timeline styling added to `fullstack-ts`; people cards and portrait framing share one component. Desktop division menus show all section links, division navigation starts at the top, and the editable anniversary banner opens a new informational `/community` page or can be dismissed. The community page is static and outside the six-page CMS registry.

The [current six-page screenshots](./ux-audit/screenshots/rescore-8/) support the latest independent scores. A separate 320px and 768px full-scroll browser check found HTTP 200, one H1, no horizontal overflow, no broken visible images, and no page errors on all six routes at both widths. A link sweep found no dead `href="#"` links or missing same-page targets among 168 visible links; all 44 distinct local cross-page hash destinations resolved. The [JavaScript loading check](./ux-audit/2026-10-05-loading-check.md) and [image loading check](./ux-audit/2026-10-05-image-loading-check.md) record transfer changes. These checks do not replace task observation, assistive-technology review, or performance measurements.

The [semantic and throttled-loading check](./ux-audit/2026-10-05-semantic-loading-check.md) found a shared route-title defect and measured one local mobile loading pass. All six public routes now have distinct browser titles; the existing public-page scenario checks them without adding a new case. The same preview rebuild revealed changed clean-install seeds conflicting with checksum-stamped earlier local rows. Bootstrap now recognizes those exact previous seed checksums, preserves the existing values and published edits, and still rejects unknown pristine mismatches. The seed job and normal Compose frontend startup pass with the existing volume. Single-run local LCP readings of 2.70–2.88 seconds under simulated throttling are diagnostic only, not production Core Web Vitals.

A [repeatable two-run mobile lab](./ux-audit/2026-10-05-mobile-vitals-lab.md) measured 2.64–2.86 second LCP and near-zero initial layout shift across the six public routes under simulated network and CPU limits. Visible hero text, rather than imagery, was the LCP element. The small local sample does not establish production Core Web Vitals or justify changing a base primitive; collect field or controlled before/after evidence before a speed-specific code change.

A follow-up Home trace in the same lab found that its 129 KB shared schema/runtime chunk finished around 2.05 seconds and was followed by a 545–660 ms main-thread task before the H1 appeared. A CPU sample points primarily to Zod parsing in that chunk. This narrows any future speed work to the public content render path while preserving validation and CMS behavior; it does not yet prove a production LCP problem or the benefit of a particular code change.

The server seed split removes the eager 195-entity catalog from browser imports and reduces each fresh public route's encoded JavaScript by about 24 KB from the previous build. Three new Home runs under the same simulated limits measured 2.55–2.72 second hero-text LCP. That overlaps the previous 2.68–2.88 second three-run trace, so the transfer saving is verified but a paint improvement is not. The rebuilt local seed job, full `check:ci`, and 49-scenario/429-step Compose behavior run pass.

A [controlled interaction timing lab](./ux-audit/2026-10-06-interaction-lab.md) measured shared mobile-menu openings at 32–48 ms and first inactive-tab selections on three routes. One Property Management tab sample reached 232 ms, while four fresh repetitions of the same action took 56–64 ms. This is action-specific local evidence, not field INP; collect real visitor interaction data before closing the speed gate or changing the base Tabs primitive.

The [keyboard and accessibility-tree check](./ux-audit/2026-10-05-keyboard-accessibility-check.md) found no unnamed exposed interactive controls on the six public routes at desktop or mobile widths. It also found that Escape from a menu link left focus on that hidden link. The shared header now restores focus to the relevant menu trigger. Its controlled menus remain present while hidden, and the mobile button has a matching open/close name. The revised existing six-page behavior verifies Enter, Escape from both trigger and link focus, visible state, and `aria-expanded` without adding a scenario. The Construction category header passes its existing focused behavior.

The [five-division inquiry journey check](./ux-audit/2026-10-05-division-inquiry-check.md) submitted each rendered division form at 390px through the live local backend and received HTTP 200 with a visible thank-you state. On simulated transport failure, all five showed an error, retained entered values, and showed no false success. This supports local contact-path completion beyond the Storage case in the Compose suite; it does not establish production SES delivery or representative visitor task success.

A later [keyboard destination check](./ux-audit/2026-10-05-keyboard-accessibility-check.md) found that following a menu section link returned focus to the document body. The shared header now moves focus to the reached section; its existing six-page behavior failed before the fix and passes on the rebuilt Compose preview. The same accessibility check found that inquiry success panels and delivery errors did not receive focus after keyboard submission. The shared form hook now focuses the feedback message on all five division pages. Property Management also returns focus to the first field after “Send another request.” The existing Storage and Property Management scenarios failed before the changes and pass in the live preview; a separate five-page browser pass verified both success and error focus.

The shared careers form now focuses its first invalid field, delivery feedback, and first field after “Submit another.” Its existing Home behavior failed before the change and passed with real local Mailpit attachment delivery; a mobile browser check confirmed the response and reset focus paths.

The [footer tap-target and contrast check](./ux-audit/2026-10-05-footer-tap-contrast-check.md) found 19–20 px clickable footer link heights on five division pages and the Construction category. One shared theme-backed quick-link component now provides 44 px mobile targets while retaining the editable footer collections. The five division cases and Construction category case failed before the change; all seven page cases then passed with 88 steps. A computed-color sample found no sub-4.5:1 text pair among 877 sampled nodes; that diagnostic is not a formal contrast or assistive-technology assessment.

A [rules-based accessibility check](./ux-audit/2026-10-05-public-accessibility-rules-check.md) on all six live routes at desktop and mobile widths found invalid Home and Development list markup, color-only inline email links on five divisions, and an unlandmarked Real Estate anniversary notice. Shared collection semantics, a named banner region, and always-underlined contact links resolved all detected axe rules on the rebuilt preview. Direct contrast calculations resolved axe's layered-background and image-caption uncertainties for the current theme; the inactive Property Management tabs clear the small-text threshold by only 0.05:1. An actual screen-reader journey remains open. An authenticated follow-up of login, registration, password reset, Home edit mode, and a mobile/desktop editor sheet found unsupported `aria-label` usage on shared item-action containers. The editor now exposes each as a named group; the revised existing touch-editor behavior passed after failing on the prior markup. A settled keyboard cycle stayed inside the Base UI sheet and Escape restored its trigger focus. The automated scan still cannot certify overlay contrast or spoken screen-reader output.

The [resume upload transport check](./ux-audit/2026-10-05-resume-upload-limit.md) found and repaired a production blocker behind the earlier local attachment path: a 10 MiB resume became about 14 MB of base64 JSON, exceeding the deployed HTTP API and Lambda payload limits. The current path uses private direct object upload and a small final request. The local 10 MiB Mailpit proof does not establish production SES delivery or the owner's mailbox policy.

## Executed sequence and acceptance gates

### 0. Align the behavior contract and establish a baseline

1. Keep the current branch and record its uncommitted state; do not overwrite existing rewrite work. Capture the six routes at 1440px, 768px, 390px, and 320px, plus keyboard and edit-mode states. Retain the current seven scores as the baseline.
2. Revise the **existing** canonical cases in [`public.feature`](../packages/cucumber/features/application/public.feature) and [`content-editing.feature`](../packages/cucumber/features/application/content-editing.feature) before implementation. In particular, the current cases explicitly require client-only forms, full mounted section order, a neutral Property Management hero placeholder, and exact Development copy/vertical rhythm. Update those expectations to the approved new behavior. Preserve each case's stable identity and its backend/frontend representation; replace no-op declarations where a new backend submission path exists.
3. Modify existing browser/behavior checks and observe the expected failures before code changes. Honor the earlier constraint: **no new test files, scenarios, or net-new tests**. Reuse or revise existing checks to cover delivery failure, mobile navigation, active tabs, and CMS editability.

**Gate:** there is one agreed behavior for each changed journey, and the old expectations no longer force the audited flaws to remain.

### 1. Fix false success and dead actions first

1. Add a public, validated inquiry contract in `@app/schemas` for the existing Property Management, Real Estate, Construction, Storage, and Development forms. Add a versioned backend route/controller/service. Reuse the existing SMTP/SES mail connection; local Compose already has Mailpit. Use an environment-configured recipient per inquiry type. Validate payload size and origin, apply abuse protection, and return a typed failure when delivery fails. The browser preserves entered values on failure and announces success only after a successful response.
2. Make the careers flow genuinely submit a resume. The current file picker retains the name but discards the `File` object ([handler](../frontend/components/CareerApplicationForm.tsx)). Keep file size/type checks on both sides; send the file to private storage and deliver a reference or attachment to the approved recipient. If the organization chooses a manual email workflow instead, replace the current success state with an explicit mail action and remove any claim that the site submitted an application.
3. Replace Construction's inert View Plans/Specs buttons with working, authorized destinations, or remove them and keep the existing request-access action. Do the same for Development's View Current/Completed buttons until real category routes/content exist. Remove Property Management's six `#` footer destinations until valid URLs or documents exist.

**Gate:** a valid local inquiry reaches Mailpit; a failed delivery leaves the form populated and shows an error; a resume reaches its intended receiver or private store; every visible button/link has an effect. No client submission creates a CMS content entity.

### 2. Unify navigation and interaction at the shared layer

1. Build one public header that accepts page identity, navigation entries, and CTA content; render it through `MarketingLayout` on all six routes. Home gets the same mobile path as the divisions. Preserve route-specific labels and the logged-in-only edit control.
2. Limit the desktop primary row to the most useful destinations, with remaining sections under an accessible More/menu affordance. Make the mobile trigger at least 44 × 44px; support focus visibility, Escape, aria-expanded, menu close on navigation, and a reliable skip link.
3. Replace the hand-built Real Estate listing tabs with the existing base Tabs primitive, maintaining listing counts, state, keyboard behavior, and CMS collection geometry. Audit other icon-only controls before deciding whether `fullstack-ts` itself needs a larger default.

**Gate:** every route has usable desktop and mobile navigation at 320px through 1440px; keyboard-only navigation reaches and operates all header items and listing tabs; edit mode still exposes the same entity controls.

### 3. Repair content and media through the CMS contract

1. Put approved portfolio/team/project imagery into the Property Management, Real Estate, and Development heroes. Add editable media fields where current semantic schemas cannot represent them; migrate existing values without discarding pending edits. Keep a neutral fallback for genuinely unavailable media, with accurate alt text or decorative treatment.
2. Replace or suppress the seven Property Management, five Storage, and three Real Estate review/placeholder states; replace Development's six numbered partner cards with verified partners or hide those cards publicly. Do not invent endorsements, project names, links, or partner identities.
3. Give Construction Current and Completed distinct headings and summaries. Until real projects are published, avoid two near-identical eight-sector grids that imply populated portfolios; keep honest empty category states and a clear inquiry path.
4. Update the clean-install seeds **and** publish corresponding changes in the running CMS. `seed-if-empty` intentionally preserves existing published edits, so seed edits alone cannot repair the live site. Public hiding must not make an empty collection impossible to add to in edit mode.

**Gate:** no public placeholder labels, dead review links, or implied projects without data; each edited media/card/section remains reachable and publishable; existing valid published edits and pending revisions survive.

### 5. Verify in the running rewrite preview and re-score

1. Run the relevant existing Cucumber backend/frontend adapters, frontend browser checks, build, typecheck, lint, format, source/behavior catalogs, and the repository's applicable root gate. Update existing checks only. Exercise the real local backend, Mailpit, DynamoDB Local, and MinIO rather than mocks at the end-to-end gate.
2. Manually inspect all six routes at the baseline widths with keyboard, public, and authenticated editor sessions. Check navigation, forms (success and failure), media, collection add/edit/reorder, preview, publish, and empty states. Keep the preview available for owner review.
3. Recapture the same 12 audit screenshots and independently re-score the same seven categories. Aim for every category at 8/10 or above. Record any category still below 8 with its remaining source cause; do not raise a score just because code changed. Check task completion and WCAG-relevant behavior separately from the subjective visual score.

**Gate:** verified local task completion and editability, no dead public actions, no failed assets or horizontal overflow, and a new audit with evidence for every score.
