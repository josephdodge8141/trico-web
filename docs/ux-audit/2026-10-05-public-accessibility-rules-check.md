# Public accessibility rules check — 2026-10-05

I injected axe-core 4.10.3 into the live local Compose preview in headless Chromium at **390 × 900** and **1440 × 900**. Each of the six public routes loaded to network idle and its H1 before the scan. The ruleset included WCAG 2.0 and 2.1 A/AA tags and axe best practices. This was a one-off runtime audit; no test file or dependency was added to the repository.

| Route               | Initial rule violations at each width | Cause                                                                                                              |
| ------------------- | ------------------------------------: | ------------------------------------------------------------------------------------------------------------------ |
| Home                |                      2 rules, 9 nodes | The timeline's `ol` contained collection `div` wrappers, leaving eight `li` elements without a native list parent. |
| Property Management |                        1 rule, 1 node | The inline contact email was distinguished only by color until hover.                                              |
| Real Estate         |                      2 rules, 2 nodes | The inline email had the same link issue; the anniversary entity wrapper left its notice outside a named landmark. |
| Construction        |                        1 rule, 1 node | The inline contact email had the same link issue.                                                                  |
| Storage             |                        1 rule, 1 node | The inline contact email had the same link issue.                                                                  |
| Development         |                      2 rules, 6 nodes | Five highlighted items declared `role=listitem` without a list ancestor; the inline email had the same link issue. |

The fixes are at their owning layers. The shared [anniversary banner](../../frontend/components/AnniversaryBanner.tsx) is a named region. The shared [editable collection](../../frontend/components/EditableCollection.tsx) can render native ordered or unordered item lists with `li` editor wrappers, so [Home](../../frontend/pages/HomeExperience.tsx) and [Development](../../frontend/pages/DevelopmentExperience.tsx) retain edit controls without breaking list semantics. The five division review-footer email links are underlined at rest through Tailwind utilities.

The rebuilt preview returned **zero detected violations** on all 12 route/width combinations. The revised existing `public.pages` behavior failed 6/6 cases before implementation and passed **6 scenarios, 84 steps** afterward. The root `check:ci` gate passed. A full Compose behavior run identified an existing editor-step selector that assumed every editable item was a `div`; it was made element-agnostic. Its focused stale-conflict scenario passed, followed by the full live Compose run: **49 scenarios, 429 steps passed**. The frontend represented all 204 canonical cases (49 exercised, 155 justified no-op). I also inspected the Home timeline and Development highlights at 390 px after rebuilding; their mobile spacing and visual hierarchy remained intact.

axe marked color contrast **incomplete**, rather than passing it, on four mobile pages and three desktop pages. The affected surfaces were Home's layered hero and banner, two inactive Property Management tabs, and image-overlay captions on Real Estate and Development. Its automated color sampler could not resolve overlapping backgrounds or images. I therefore checked those rendered color pairs separately at 390 px and 1440 px. Chromium Canvas converted their computed OKLCH/OKLab colors to sRGB; I composited translucent foreground and background layers, then applied the [W3C relative luminance and contrast formula](https://www.w3.org/WAI/WCAG21/Techniques/general/G18). The [small-text criterion is 4.5:1](https://www.w3.org/TR/wcag/#contrast-minimum).

| Surface                                    | Calculated contrast | Backdrop assumption                                                                                                                                                                                    |
| ------------------------------------------ | ------------------: | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Home anniversary text                      |             14.45:1 | Opaque primary banner background.                                                                                                                                                                      |
| Home hero heading                          |    At least 15.64:1 | Included the decorative blue orb at its full declared opacity over the solid hero background.                                                                                                          |
| Home hero description                      |     At least 9.21:1 | Same conservative orb blend.                                                                                                                                                                           |
| Home hero badge text                       |    At least 14.12:1 | Included both the badge tint and decorative orb at full declared opacity.                                                                                                                              |
| Both inactive Property Management tabs     |              4.55:1 | Each uses the same 60%-opacity foreground over the same opaque muted tab list. This passes narrowly in the current theme.                                                                              |
| Real Estate and Development image captions |    At least 12.38:1 | White text over an 85%-opaque dark overlay, with a pure white image beneath it. White is the lightest possible image pixel for this overlay and thus gives the lowest contrast against its white text. |

The calculated pairs exceed the specified minimum in this running theme, including the worst-case image caption backdrop. This resolves the listed **axe-incomplete pairs** for the current colors, not every possible contrast combination or a full WCAG conformance claim. The [earlier broader computed-color sample](./2026-10-05-footer-tap-contrast-check.md) had no sub-4.5:1 pairs among its 877 sampled nodes. The inactive tabs have only a 0.05:1 margin, so any theme change should recheck them. A real screen-reader journey and review of owner-supplied content remain open.

## Authenticated follow-up — 2026-10-06

I ran the same one-off ruleset at 390 px and 1440 px on `/login`, `/register`, `/request-reset`, Home with edit mode active, and the open Corporate contact editor sheet. The three auth pages had **zero detected violations and zero incomplete rules** at both widths. The editor and sheet had zero detected violations, but the initial scan marked 28 Home item-action containers as incomplete under `aria-prohibited-attr`: their `aria-label` was on a generic `div` without a semantic role. The shared [EditableItem](../../frontend/components/EditableItem.tsx) now gives those controls `role="group"`, preserving their item-specific accessible names. The existing touch-editor scenario failed before the fix and passed afterward (**1 scenario, 7 steps**); the new scan no longer lists `aria-prohibited-attr` as incomplete.

The open sheet still produces an `aria-hidden-focus` **incomplete** result for Base UI's inert page root and two focus guards. To check actual keyboard behavior, I opened the sheet at both widths and pressed Tab 24 times with focus settling after each key. Focus remained inside the dialog at every settled stop; the page root was marked `aria-hidden` and `data-base-ui-inert`. Escape closed the sheet and returned focus to the original Edit Corporate contact button. This supports the current keyboard path but does not prove screen-reader behavior across browsers. The sheet and edit mode also retain some automated color-contrast incompletes where overlays obscure the sampler.
